# Code Reviewer

## 适用场景（When to invoke）
- 用户说“帮我做代码审查/Review 这段代码”
- 合并前自检、发布前扫雷
- 线上 bug 复盘，需要定位潜在风险点

## 输入要求（Inputs）
- 代码片段或文件路径
- 目标：更安全 / 更快 / 更易读 / 更一致（任选其一或多项）
-（可选）语言/框架/代码规范要求

## 工作流程（Workflow）
1. 快速概览：识别模块职责、关键数据流、外部依赖
2. 风险扫描：空值/越界/并发/资源释放/安全/性能
3. 可维护性检查：命名、重复、复杂度、测试覆盖建议
4. 产出结论：按“高/中/低”优先级列出问题与修复建议
5. 如用户允许：提供最小改动的补丁建议与验证点

## 输出格式（Outputs）
- 高优先级问题（必须改）：问题描述 + 影响 + 建议修复方式
- 中优先级问题（建议改）：问题描述 + 取舍/替代方案
- 低优先级建议（可选）：一致性/可读性/小重构建议
- 推荐下一步：补测试/补监控/重构切分等

## 示例（Examples）
### 示例 1：审查单个函数
- 用户输入：`请 review 这个函数，重点看边界条件和性能：<paste code>`
- 期望行为：列出高/中/低问题清单，并给出可直接落地的改动建议
